# Plan 04-04: Payment Processing Modal, Failure/Pending Recovery Cards, Printable In-App Receipt, Wizard Lock & E2E Verification

## Goal

Assemble the complete Stage 4 Review, Payment & Submission experience: multi-stage processing modal (`PaymentProcessingModal`), in-context failure recovery card (`PaymentFailureCard`), pending verification card (`PaymentPendingCard`), printable in-app receipt (`ReceiptCard`), draft submission locking, `ReviewScreen` assembly into `App.tsx`, and full Playwright E2E verification.

## Tasks

### 1. Payment Modal, Error Recovery & Receipt Components

- Create `src/features/review/PaymentProcessingModal.tsx`:
  - Accessible modal dialog using `role="dialog"` and `aria-modal="true"`.
  - Multi-step animated progress indicators:
    - Step 1: "Connecting to payment gateway…" (0-600ms)
    - Step 2: "Authorizing with bank…" (600-1300ms)
    - Step 3: "Confirming transaction…" (1300-2000ms)
  - Disables backdrop click and dismiss actions during active processing to eliminate double-submission.
- Create `src/features/review/PaymentFailureCard.tsx`:
  - In-context alert card with `#FEF2F2` background and red border.
  - Clear decline reason copy ("Payment declined by bank: Insufficient funds or invalid OTP").
  - Dual action buttons: "[Retry Payment]" (primary) and "[Choose Another Method]" (outline).
  - Preserves 100% of entered application and payment form answers.
- Create `src/features/review/PaymentPendingCard.tsx`:
  - Amber alert card with `#FFFBEB` background for bank pending/timeout outcomes.
  - Manual "[Check Status]" button that re-polls `IPaymentService.confirm` and resolves to success.
- Create `src/features/review/ReceiptCard.tsx`:
  - Official receipt card with transaction reference ID (`PAY-XXXXXX`), timestamp, applicant name, passport number, visa type, and itemized fee breakdown.
  - Actions: "Download Receipt (PDF)" and "Print Receipt" (triggers `window.print()` with `@media print` CSS hiding non-receipt UI elements).
- Create unit/component tests for modal, failure card, pending card, and receipt card.

### 2. ReviewScreen Assembly & App Integration

- Create `src/features/review/ReviewScreen.tsx`:
  - Connects `StageReviewCard`s for Visa Selection, Personal Info, and Document Uploads.
  - Renders `DeclarationCheckbox` with required state error handling.
  - Renders `FeeBreakdownCard` with live fee totals.
  - Renders `PaymentMethodSelector` and active method form (UPI / Card / Netbanking).
  - Renders `PaymentProcessingModal`, `PaymentFailureCard`, `PaymentPendingCard`, and `PaymentScenarioBar`.
  - Handles "Pay Now" submission:
    - Validates declaration and payment method inputs.
    - Opens `PaymentProcessingModal` and executes `executeMockPayment`.
    - On success:
      - Calls `MockNotificationService.sendEmail` and `sendSms`.
      - Dispatches `Toast` confirmation: "Receipt and confirmation sent to your email and phone".
      - Dispatches `SUBMIT_PAYMENT_SUCCESS` event to wizard machine with generated `PaymentReceiptData`.
      - Wizard auto-advances to Stage 5 (`confirmation`) with draft locked (`submitted: true`).
    - On failure / timeout:
      - Mounts `PaymentFailureCard` or `PaymentPendingCard` in-context with retry options.
- Create `src/features/review/index.ts` exporting `ReviewScreen`, `ReceiptCard`, `EditingBanner`, and review helpers.
- Update `src/App.tsx`:
  - Replace the Stage 4 review-payment placeholder with `<ReviewScreen />`.
  - Render `ReceiptCard` in Stage 5 confirmation placeholder when `answers.receipt` exists.

### 3. Full Playwright E2E Test Suite

- Create `tests/e2e/stage4-review-payment.spec.ts`:
  - Test 1: Complete end-to-end journey from Stage 1 through Stage 4, verify all answers appear in Review summary cards.
  - Test 2: Click "Edit" on Personal Details from Stage 4, verify sticky `EditingBanner` appears, change email/phone, click "Return to Review", verify updated details appear in Review.
  - Test 3: Attempt payment without checking declaration checkbox, verify error summary banner appears.
  - Test 4: Select UPI (QR Code mode), authorize payment under Success scenario, verify multi-stage modal, receipt generation, and transition to Stage 5.
  - Test 5: Select Card payment, set scenario to "Card Declined", attempt payment, verify `PaymentFailureCard` appears with entered card details intact, click "Retry Payment" with Success scenario, verify successful recovery and submission.
  - Test 6: Verify submitted application is locked to read-only mode and cannot mutate draft answers.
