# Plan 04-01: Payment Domain Models, Fee Calculator, Input Formatters & Wizard State Machine Topology

## Goal

Build the foundational domain models, fee calculation engine, payment input formatters/validators, and extend the XState wizard machine to support deep-link review editing round-tripping (`returnToReview`) and locked draft states upon submission.

## Tasks

### 1. Review & Payment Domain Types

- Create `src/features/review/types.ts`:
  - `PaymentMethodType`: `'upi' | 'card' | 'netbanking'`
  - `UpiMode`: `'vpa' | 'qr'`
  - `PaymentScenario`: `'success' | 'declined' | 'timeout' | 'network_error'`
  - `FeeBreakdown`:
    - `processingFee: number`
    - `governmentFee: number`
    - `platformFee: number`
    - `totalAmount: number`
    - `currency: string`
  - `PaymentReceiptData`:
    - `transactionId: string`
    - `referenceNumber: string`
    - `paidAt: string`
    - `applicantName: string`
    - `passportNumber: string`
    - `destinationCountry: string`
    - `visaType: string`
    - `paymentMethod: PaymentMethodType`
    - `paymentMethodDetails: string`
    - `feeBreakdown: FeeBreakdown`
  - `StageSummaryItem`:
    - `id: string`
    - `stageNumber: number`
    - `title: string`
    - `stepId: string`
    - `fields: Array<{ label: string; value: string; isDocument?: boolean; docId?: string; fileBlob?: Blob }>`

### 2. Fee Calculation Engine & Input Formatters

- Create `src/features/review/fees.ts`:
  - `calculateFeeBreakdown(answers: Record<string, unknown>): FeeBreakdown`:
    - Reads `destinationCountry` and `visaId` / `visaType` from answers.
    - Calculates `processingFee` via `processingFeeFor(country, visaType)`.
    - Uses `GOVERNMENT_FEE` (₹5,000) and `PLATFORM_FEE` (₹1,500).
    - Derives `totalAmount = processingFee + governmentFee + platformFee`.
- Create `src/features/review/fees.test.ts`.
- Create `src/features/review/formatters.ts`:
  - `formatCardNumber(val: string): string` (4-4-4-4 digit spacing up to 16 digits).
  - `formatCardExpiry(val: string): string` (MM/YY auto-slash formatting).
  - `formatCvv(val: string): string` (3-4 digit numeric mask).
  - `isValidUpiVpa(vpa: string): boolean` (validates `^[a-zA-Z0-9.\-_]{2,256}@[a-zA-Z]{2,64}$`).
  - `isValidCardNumber(val: string): boolean` (16 digits with Luhn algorithm check).
  - `isValidCardExpiry(val: string): boolean` (valid future MM/YY date check).
  - `isValidCvv(val: string): boolean` (3 or 4 digit numeric check).
- Create `src/features/review/formatters.test.ts`.

### 3. Wizard Machine & Step Selector Integration

- Update `src/features/wizard/types.ts`:
  - Add `returnToReview?: boolean` to `WizardMachineContext`.
  - Add `{ type: 'RETURN_TO_REVIEW' }` to `WizardEvent`.
  - Add `{ type: 'GOTO'; stepId: StepId; returnToReview?: boolean }` support.
  - Add `{ type: 'SUBMIT_PAYMENT_SUCCESS'; receipt: PaymentReceiptData }` to `WizardEvent`.
- Update `src/features/wizard/machine.ts`:
  - Handle `RETURN_TO_REVIEW`: transitions to `review-payment` step and clears `returnToReview: false`.
  - Handle `GOTO` with optional `returnToReview: true` parameter.
  - Handle `SUBMIT_PAYMENT_SUCCESS`: updates answers with `paymentCompleted: true`, `submitted: true`, `receipt`, and transitions to `confirmation`.
  - Guard transitions when `answers.submitted === true` to preserve read-only state.
- Update `src/features/wizard/validators.ts`:
  - Add `validateReviewPaymentStep(answers: Record<string, unknown>): Record<string, string>`:
    - Validates `declarationConfirmed === true`.
    - Validates `paymentCompleted === true` (for stage completion).
- Update `src/features/wizard/selectors.ts`:
  - Implement `isReviewPaymentStepValid(answers)` checking declaration and payment.
  - Update `deriveStepStatus('review-payment', answers, currentStepId)`.
- Update `src/features/wizard/machine.test.ts`, `validators.test.ts`, and `selectors.test.ts`.
