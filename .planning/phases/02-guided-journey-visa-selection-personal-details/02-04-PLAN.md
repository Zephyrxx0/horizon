# Plan 02-04: Stage 2 — Personal Details Multi-Screen Sub-steps

## Goal

Implement Stage 2 (Personal Details) as three dedicated, accessible sub-steps (2a: Identity & Passport, 2b: Contact & Address, 2c: Visa-Specific Details) with progressive disclosure, input auto-formatting, on-blur validation checkmarks, expiry warnings, and accessible error summaries.

## Tasks

### 1. Sub-step 2a: IdentityStep (`PERS-01`, `PERS-02`, `PERS-04`, `PERS-05`, `PERS-06`)

- Create `src/features/personal/IdentityStep.tsx`:
  - Fields: `firstName`, `lastName`, `dateOfBirth`, `gender`, `nationality` (defaults to "India"), `passportNumber` (auto-formatted with `formatPassportNumber`), `passportIssueDate`, `passportExpiryDate`.
  - On expiry input blur/change: evaluate `getPassportExpiryStatus`. If `<6` months, display `ExpiryWarning` amber card with required checkbox `passportExpiryConfirmed`.
  - Blur validation: display green checkmark on valid fields or inline constructive error message.
  - Sub-step Back button (returns to Stage 1) and Continue button (validates fields; if errors, scrolls to top and focuses `ErrorSummary`).
- Create `src/features/personal/IdentityStep.test.tsx` with unit and `vitest-axe` tests.

### 2. Sub-step 2b: ContactStep (`PERS-01`, `PERS-03`, `PERS-06`)

- Create `src/features/personal/ContactStep.tsx`:
  - Fields: `email`, `phone` (auto-formatted with `formatPhoneNumber`), `addressLine1`, `addressLine2`, `city`, `state`, `pincode`.
  - Blur validation: email format, 10-digit phone format, 6-digit PIN code format.
  - Sub-step Back button (returns to 2a) and Continue button (advances to 2c or flags errors in `ErrorSummary`).
- Create `src/features/personal/ContactStep.test.tsx` with unit and `vitest-axe` tests.

### 3. Sub-step 2c: VisaSpecificStep (`PERS-01`, `PERS-06`)

- Create `src/features/personal/VisaSpecificStep.tsx`:
  - Progressive disclosure based on `visaCategory` / `visaId` in answers:
    - **Tourism / Visitor**: `travelStartDate`, `travelEndDate`, `stayAddress` / `hotelName`.
    - **Business**: `companyName`, `businessContactPerson`, `businessAddress`, `invitationLetterRef`.
    - **Student**: `institutionName`, `courseName`, `sevisOrCasNumber`, `institutionAddress`.
    - **Work**: `employerName`, `jobTitle`, `workLocation`, `workPermitOrPetitionNumber`.
  - Blur validation and constructive errors.
  - Sub-step Back button (returns to 2b) and Continue button (advances to Stage 3 / next stage).
- Create `src/features/personal/VisaSpecificStep.test.tsx` with unit and `vitest-axe` tests.

### 4. Stage 2 Orchestrator Screen (`PersonalDetailsScreen.tsx`)

- Create `src/features/personal/PersonalDetailsScreen.tsx`:
  - Renders sub-stepper indicator (2a: Identity → 2b: Contact → 2c: Details).
  - Switches active sub-step based on machine `currentStepId` or sub-step state.
  - Integrates `ErrorSummary` at the top of the step card.
- Create `src/features/personal/PersonalDetailsScreen.test.tsx` testing the full sub-step navigation flow.
- Export all from `src/features/personal/index.ts`.

## Verification

- `pnpm vitest run src/features/personal/` passes with all tests and zero axe violations.
