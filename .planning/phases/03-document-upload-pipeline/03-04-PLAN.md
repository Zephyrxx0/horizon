# Plan 03-04: Documents Screen, Wizard Topology Integration & E2E Verification

## Goal

Integrate the document upload components into the Stage 3 `DocumentsScreen`, wire the wizard state machine and step status selectors, integrate draft resumption and persistence, and verify the end-to-end user journey with unit, component, accessibility, and Playwright tests.

## Tasks

### 1. Wizard Topology, Validators & Selectors Integration

- Update `src/features/wizard/types.ts`:
  - Ensure `WizardAnswers` includes `documents: Record<string, DocumentAttachment>` and `visaType?: string`.
- Update `src/features/wizard/validators.ts`:
  - `validateDocumentsStep(answers: WizardAnswers): { isValid: boolean; missingMandatorySlots: string[]; unacknowledgedBlurWarnings: string[] }`:
    - Looks up mandatory slots for `answers.visaType`.
    - Checks that every mandatory slot (and its sub-slots) has an attachment in `answers.documents`.
    - Checks that any attachment with `isBlurWarning === true` has `isBlurWarningAcknowledged === true`.
- Update `src/features/wizard/selectors.ts`:
  - Update `deriveStepStatus` for `'documents'` step to return `complete`, `current`, `incomplete`, or `needs-attention`.
  - Update `getFirstIncompleteStep` so returning drafts with incomplete documents correctly resume on `'documents'`.
  - Update `deriveProgress` to factor Stage 3 completion.
- Update `src/features/wizard/validators.test.ts` and `src/features/wizard/selectors.test.ts`.

### 2. DocumentsScreen Container Component

- Create `src/features/documents/DocumentsScreen.tsx`:
  - Reads `answers`, `send`, and `validationErrors` from `useWizardContext`.
  - Determines required document slots using `getDocumentSlotsForVisa(answers.visaType || 'us-tourist')`.
  - Renders sticky top progress header: "Documents: {readyCount} of {mandatoryTotal} mandatory ready".
  - Renders `ErrorSummary` at the top when applicant attempts to continue with missing mandatory documents or unacknowledged blur warnings.
  - Renders **Mandatory Documents** section with `DocumentSlotCard` for each mandatory item.
  - Renders **Optional Supporting Documents** section with `DocumentSlotCard` for each optional item.
  - Integrates `DocumentPreviewSheet` and `SampleGuidanceSheet` modals.
  - Navigation footer: "Back" button (returns to Stage 2) and "Continue to Review & Payment" button (validates and advances to Stage 4).
- Create `src/features/documents/index.ts` exporting `DocumentsScreen`.
- Create `src/features/documents/DocumentsScreen.test.tsx` testing rendering, slot interactions, error summary display, and zero axe violations.

### 3. App Routing Integration & AppShell

- Update `src/App.tsx`:
  - Render `DocumentsScreen` when `currentStepId === 'documents'`.
  - Ensure stepper reflects Stage 3 "Documents (5 min)" as active step.

### 4. Playwright E2E Test Suite

- Create `e2e/documents-upload.spec.ts`:
  - Complete Stage 1 (Visa Selection) and Stage 2 (Personal Details) to reach Stage 3.
  - Upload sample image files to Passport Bio, Passport Address, and Photo slots.
  - Verify client-side compression executes and "✓ Ready • {size}" badge displays.
  - Open and verify `SampleGuidanceSheet` and `DocumentPreviewSheet`.
  - Download template from optional slot and verify file creation.
  - Reload browser and verify attached files and "✓ Ready" statuses persist from IndexedDB (`STATE-03`, `STATE-04`).
  - Click "Continue" and verify advancement to next stage.
