# Plan 05-04: Confirmation Screen Orchestration, AppShell Integration & E2E Verification

<objective>
Wire the complete Stage 5 Confirmation screen, integrate header tracking/backup actions into the AppShell, and verify the full post-submission journey with Playwright E2E tests:
1. `ConfirmationScreen`: Root container for Stage 5 composing `ReferenceCard`, `ReceiptCard`, `StatusTimelineCard`, `InterviewChecklistCard`, and `SentNotificationsCard` (CNFRM-01..04, TRCK-02, TRCK-03).
2. `AppShell` & `SaveIndicator`: Add "Track Application" and "Backup Draft" buttons in `AppHeader` and wire `SaveIndicator` / `ResumeBanner` clicks to open `DraftBackupModal` and `TrackingModal` (TRCK-01, STATE-05).
3. Playwright E2E test suite (`tests/e2e/stage5-confirmation.spec.ts`) validating end-to-end confirmation, reference copying, WhatsApp sharing, timeline scenario stepping, checklist downloads, standalone tracking, and duplicate application detection.
</objective>

<threat_model>

- **Threat:** Unhandled navigation or state resets leaving submitted applicants with missing receipts or empty reference numbers.
  - **Mitigation:** Fallback reference generator and receipt data validation inside `ConfirmationScreen` ensuring confirmation always displays complete submitted records.
- **Threat:** Modal triggers in header breaking keyboard tab order or screen reader focus flow.
  - **Mitigation:** Accessible `button` elements with explicit aria labels and focus trapping in all opened sheets.
    </threat_model>
