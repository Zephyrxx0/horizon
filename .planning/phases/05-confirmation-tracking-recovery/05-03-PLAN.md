# Plan 05-03: Recovery, Standalone Tracking & Duplicate Detection Modals

<objective>
Build the recovery, standalone tracking, and duplicate detection components:
1. `TrackingModal`: Accessible modal opened on-demand from `AppHeader` or duplicate warning card allowing applicants to enter a reference number (`VR-YYYY-XXXXXX`), look up status, and inspect the live status timeline (TRCK-01).
2. `DraftBackupModal`: Accessible modal for generating 8-character backup codes (`VR-XXXXXX`), copying codes, sending simulated email, and restoring drafts across devices with conflict comparison dialog (STATE-05).
3. `DuplicateWarningCard`: Inline amber warning card integrated into `PersonalIdentityForm` on passport blur offering `[Track Existing Application]` (opening pre-filled tracking modal) and `[Continue Anyway]` (STATE-06).
</objective>

<threat_model>

- **Threat:** Overwriting an active in-progress draft during restore without applicant consent.
  - **Mitigation:** Mandatory conflict comparison dialog highlighting local vs. remote draft differences with explicit replace/keep buttons.
- **Threat:** Duplicate detection blocking legitimate applicant progression on false positives.
  - **Mitigation:** Explicit "Continue With New Application Anyway" override button dismissing the warning.
- **Threat:** Keyboard focus escaping tracking or backup modals.
  - **Mitigation:** Trap focus using accessible `Sheet` primitive with `aria-modal="true"` and restore focus on close.
    </threat_model>
